# SoundPrep 0.11.0

Released 2026-10-22. Source and release assets are available from [PontakuAudio/SoundPrep](https://github.com/PontakuAudio/SoundPrep).

Normalize now runs in the bundled native helper, using REAPER's decoder and C++ DSP. Python, FFmpeg and ffprobe are no longer needed for normal use. The former Python analyzer remains in the source repository for development comparisons and is excluded from runtime ZIP/ReaPack packages.

The main action is `SoundPrep.lua`. Manual-install packages are `soundprep-0.11.0-macos-universal.zip` and `soundprep-0.11.0-windows-x64.zip`, each containing a `SoundPrep` folder. Native helper filenames and existing project identifiers remain compatible.

The public source includes the existing Lua and Native code. The new C++ analysis engine and its internal tests/reference implementation are distributed only as compiled code inside the existing Windows DLL and macOS dylib. Project contributions remain MIT licensed, including the binaries. Third-party licenses and attribution remain intact.

The public checkout retains the existing source but cannot rebuild the complete v0.11.0 helper without the private analysis implementation. Public CI instead checks the versions, formats and SHA-256 hashes of reviewed prebuilt helpers, runs public Lua/package tests, and creates runtime packages. Internal Native/DSP builds and tests run separately. See [source and binary distribution](https://github.com/PontakuAudio/SoundPrep/blob/v0.11.0/docs/source-distribution.md) for the scope and release process.

- Keep LUFS MaxM as the default and preserve existing presets' selection. It measures the maximum 400 ms momentary window on a 100 ms grid, with dual-mono evaluation for mono preview.
- Add time-varying, free-field Zwicker loudness. Max is the default summary when choosing Zwicker; P95 is optional. Evaluation covers the whole source plus a fixed 400 ms response tail. P95 includes source silence and this tail.
- Store target sones and assumed SPL calibration per preset, including Raw. Defaults are 8 sones and RMS −20 dBFS = 79 dB SPL. This is an analysis assumption, not automatic measurement of speaker playback SPL. Candidate gains are reevaluated through the nonlinear model.
- Evaluate mono as one loudness series; for stereo, evaluate channels separately and combine them as `sqrt(NL² + NR²)`. This is not a binaural model.
- Preserve multichannel policy: Downmix ON analyzes the existing discrete or AmbiX W/Y stereo mapping; OFF uses the loudest independent channel, or AmbiX W, and applies one common gain. OFF continues to bypass Macro FX. REAPER-decodable sources from 1 to 128 channels are supported.
- Keep source True Peak guard separate from the loudness target. The native interpolator estimates peaks independently of the old FFmpeg resampler, so results need not be bit-identical. Neither source normalization nor this guard limits the output of later FX.
- Preserve asynchronous analysis and gradual correction of an active preview without Replay. Stop/Pause does not start playback on completion. D&D captures the final target gain even while the preview is transitioning. Old analyzer caches are not reused as native measurements.
- Bound estimated Zwicker memory to 1 GiB per job, approximately eight minutes of stereo input. Oversized jobs report an explicit error directing the user to LUFS MaxM or a shorter source. Temporary disk use and processing time also grow with source length and channel count.

Requires REAPER 7.35+, SWS, JS_ReaScriptAPI and ReaImGui. Update both scripts and the native helper, save your work, and restart REAPER; the previous helper does not provide the new analysis APIs. Packages contain macOS Apple Silicon/Intel universal or Windows 10/11 REAPER x64 helpers.

The Zwicker C++ port has been compared against MoSQITo 1.2.1 and the supplied optimized kernels using tones, noise, impulses, short bursts, gain changes and independent stage tests. Numeric tests are not standards certification. In real REAPER on macOS arm64, 14 native-analysis cases pass across 44.1/48/96 kHz: LUFS, Zwicker Max/P95, multichannel discrete and AmbiX policies, calibration changes, very low digital levels and EOF transients. Active gain transitions, stopped playback and cached replay are also covered. Eleven actual rendered D&D cases pass: six LUFS cases, plus Zwicker Max with generic multichannel Downmix OFF/ON and AmbiX OFF/ON, and Zwicker P95 with AmbiX ON. These check channel counts, peaks, polarity, common source gain and Macro FX bypass with Downmix OFF. Native tests pass with address, undefined-behavior, float-cast-overflow and thread sanitizers. The new analysis path has not been verified in a real Windows host.
